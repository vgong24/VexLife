# VexLife Assortment — Round 2 Vex node practicum 01

[VXG RealForever]

This is a bounded design practicum inside the existing PR #841 Assortment lane.
It extends the already-proved I13B2 preview rather than replacing it.

## Human question

What should it feel like to enter **Vex** as a companion-legibility node while
conversation remains present as the person moves through VexLife?

## Bounded delta

- remove the old Home placeholder/example subtrees for Self Development,
  Vex Home Product, and Local Vex from this preview;
- preserve Continue, Projects, Frontier and the inherited Continuity behavior;
- add one Vex Home node;
- restore the Reference / Evolution selector to the app bar beside the layout
  controls;
- project Vex from existing current semantic-frame, companion-turn,
  companion-availability, capability and permission seams;
- keep Vex presence/conversation visible while another Evolution surface is
  active;
- bridge the visible Vex composer into the canonical Chat composer rather than
  creating a second message owner;
- visibly mark Memory, mutual preference, Vessel and broader Perception truth as
  held/future where their current source is not yet a lived product runtime.

## One Vex identity

This practicum presents exactly one companion identity: **Vex**.

Legacy implementation names such as `guide-controller`, `guideWindow`,
`feature.vexlife.screen-aware-guide`, and host/carrier terminology in proof
machinery do not form separate Vex roles, personas, identities, or relationship
surfaces. The existing Guide controller is reused only as inherited rendering
plumbing for the one visible Vex presence. An execution "host" means the machine
running a qualified proof, never another role of Vex.

Capabilities, permissions, contexts, and presentation modes may vary without
fragmenting companion identity.

## Proof

`PROOF.e2e.mjs` reconstitutes the exact proved I13B2 predecessor first and then
checks the Vex/Home delta in a real Chromium runtime. It captures desktop Vex,
Continue-with-companion, and compact mobile evidence.

The practicum may teach the next design edge. It does not itself adopt a
canonical Vex-node product schema.

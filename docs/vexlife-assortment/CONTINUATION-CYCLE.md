# VexLife Assortment — Continuation Cycle

[VXG RealForever]

## Purpose

This is the reusable operating cycle for continuing VexLife Assortment without
turning every fresh ChatGPT instance, retry or design checkpoint into a new lane.

It separates:

```text
stable continuation grammar
from
per-run / per-Round parameters
```

It is an Assortment continuity contract. It does not replace VexLife repository
culture, product semantic owners, Local Source Workspace source, VexRelay source,
GitHub live state, or protected human decisions.

## Permanent non-collapse laws

```text
FRESH_THREAD != NEW_ROUND
FRESH_INSTANCE != NEW_WRITER
FRESH_INSTANCE != NEW_WORKSPACE
FRESH_INSTANCE != NEW_BRANCH_OR_PR
RETRY != NEW_SEMANTIC_TASK
NEW_ATTEMPT != NEW_TASK
CHECKPOINT != TERMINAL
MERGE != POST_MERGE_VERIFICATION
DESIGN_PR != IMPLEMENTATION_PR
PROJECT_SOURCES != MUTABLE_CURRENT_STATE
STATIC_HANDOFF != LIVE_CURRENTNESS
```

A new Round is earned by a real human/design phase boundary. It is not created by
provider turnover, context compaction, a new ZIP, a failed attempt or a merged
checkpoint inside the same continuing design phase.

the evidence exists. The Round log derives durable current design continuity and
keeps exact discussion refs for deeper descent.

## Reusable cycle

### C00 — Ground canonical repository

Verify `vgong24/VexLife`, repository ID `1317660990`, live main and live
`AGENTS.md`. Follow the repository's current orientation contract.

Read only the orientation `requiredSources` that bear on the next effect. A
nested source does not automatically widen the caller's scope.

### C01 — Adopt Assortment occupancy

Search current canonical state before creating anything.

Prefer, in order:

```text
existing compatible Assortment PR/branch/workRef/claim
-> existing compatible local workspace/custody
-> bounded successor only when the prior lane is truly terminal
-> new Round only when the design phase actually changed
```

Duplicate continuity is a defect, not harmless bookkeeping.

### C02 — Read current design position

Read:

```text
CURRENT.md
CONTINUATION-CYCLE.md
active Round log
only the exact source/owner records named by those files for the next function
```

Derive the next **unconsumed function**, not merely the latest timestamp.

### C03 — Resolve Operations only when implicated

When currentness, authority, host execution, lane recovery or cross-repository
Operations is actually implicated, consume the live accepted Vextreme-SDK
Operations front door.

Current pattern:

```text
ground live SDK repository
-> current CLAUDE.md / stable root-onboarding front door
-> npm run orient semantics
-> current-entry / Event-driven Work Awareness as needed
-> question-scoped Federated Orientation
-> finite required-source descent
-> explicit semantic stop
```

Do not ambiently bulk-read historical Root issues, static roadmaps, or old Local
Operations/VexRelay manuals. Descend into them only when one named unresolved
obligation requires them.

A Durable Lane Runtime/resume capsule may be consumed when an exact accepted
lane aggregate exists; do not recreate its state from chat prose.

### C04 — Select the exact execution surface

Execution surface is chosen per effect, not per tradition.

```text
exact connected provider effect available + authorized
  -> CONNECTOR_DIRECT

host-local source/workspace effect required
  -> consume current Local Source Workspace status/source
  -> adopt exact existing workspace when compatible
  -> otherwise allocate through the current accepted source-managed route

Relay-required repository/host proof
  -> read live source.vexrelay.current-contract/v1
  -> select current named recipe/adapter
  -> form a fresh attempt only when needed
```

Do not route through VexRelay merely because an old Round used Relay. Do not use
a local AUTHORING workspace merely because one existed previously. Do not use
GitHub Actions as a substitute for a proof class whose selected owner is
VexRelay/host-local evidence.

### C05 — Continue design before implementation

Resume the current Assortment design function. Preserve:

```text
human intent
current canonical semantic owners
Reference/Evolution distinction
append-only finding/history evidence
derived current feedback
held product-source boundaries
```

A practicum may simulate. It does not silently become canonical product source.

~~~

Fix common harness defects in the kit rather than forking another copy into a new preview package.

### C06 — Preserve material design continuity

After a material design exchange, update the active Round lineage through the
smallest authorized durable effect.

Prefer:

```text
one current Round log
+ CURRENT.md when the current projection changed
+ exact immutable PR/comment refs for source evidence
```

Do not append a new file for every sentence or duplicate full conversation
transcripts.

### C07 — Source adoption is a separate edge

When a design has earned source adoption:

1. re-ground accepted main;
2. re-ground exact semantic/component/presentation owners;
3. re-ground active authored + generated path custody;
4. source-place the smallest membrane;
5. allocate/adopt the lawful writer surface;
6. bind localization/accessibility/recovery/effect contracts;
7. implement only the admitted source;
8. regenerate exact generated consequences from current source;
9. prove rendered/native behavior actually claimed.

A design acceptance does not pre-authorize this stage.

### C08 — Freeze a checkpoint only when useful

A checkpoint is earned when the current Round has a coherent, reviewable
decision boundary. Freeze exact head/tree/path/source identities before
Independent Assurance.

Do not merge because a PR is old, large, mergeable, or inconvenient to keep open.

### C09 — Lifecycle progression

When exact source/evidence is clear, progress each gate separately:

```text
source-owner proof
-> fresh claimless Independent Assurance
-> lifecycle/currentness
-> Formal Review
-> READY
-> fresh pre-merge reread
-> ordinary expected-head merge
-> post-merge accepted-main verification
-> claim/custody release
-> dependent wake discovery
-> terminal return
```

A previous gate is evidence, not automatic authority for the next one.

### C10 — Form a successor only after terminality

A successor preserves lineage but gets fresh semantic work identity only when the
next work is genuinely a new semantic task or the previous lane is terminal.

A merge inside Round 2 does not automatically create Round 3.

## Progression Grammar — idea to accepted work and later extension

This is the reusable **meta-template** for the relationship between Assortment
nodes and canonical VexLife owners. It answers what must be understood before
moving from an idea to real work, and where completed work re-enters when it
produces a new idea.

It is not another lifecycle owner. Each station projects/reuses the rightful
owner named by current VexLife source.

~~~text
01 CAPTURE + PROVENANCE
02 LINEAGE + CURRENTNESS
03 SHAPE + PLACE
04 ADMIT / REUSE
05 CONSTRUCT
06 EXECUTE / COORDINATE
07 HEALTH + PROOF
08 ACCEPT + COMPLETE
09 PRESERVE + EXTEND
~~~

### G01 — Capture + provenance

Human question:

> What idea matters enough not to lose?

Ordinary projection: **Frontier**.

Required:

- protect human intention and origin/source lineage;
- preserve uncertainty about placement;
- capture without silently creating Project, Feature, branch, writer or work;
- make unplaced ideas retrievable.

~~~text
IDEA_CAPTURED != PROJECT_ADMITTED
UNPLACED != ORPHANED
~~~

Primary work/progress owner remains Intent Queue / Intent Workgraph.

### G02 — Lineage + currentness

Human question:

> Does this already have a life somewhere?

Join exact current sources for:

~~~text
issue / PR / workRef
projectRef / featureRef
source owner / current candidate
accepted / held / superseded trajectory
~~~

A local Frontier seed never overwrites realized current work.

~~~text
CAPTURED_SEED_STATE != LIVE_TRAJECTORY_STATE
EXISTING_TRAJECTORY -> RESUME_OR_INSPECT__NOT_DUPLICATE_FORMATION
~~~

### G03 — Shape + place

Human question:

> What kind of thing is this, and where does it belong?

Possible projections include:

~~~text
existing Project extension
new Project candidate
Feature candidate
shared capability
multi-home concern
Home/presentation candidate
parked/held idea
~~~

Placement is classification/context, not execution authority.

### G04 — Admit / reuse

Human question:

> Has bounded work identity actually been earned?

Reuse an existing owner whenever current source already supplies one. Otherwise
admit only the smallest rightful Project / Feature / work identity with exact
parent and source lineage.

~~~text
CAPTURE != ADMISSION
PLACEMENT != ADMISSION
ADMISSION != EFFECT_AUTHORITY
~~~

Parallel work should not widen before identity, owner and duplicate-currentness
questions are sufficiently resolved.

### G05 — Construct

Human question:

> How does admitted intent become bounded design/work?

Reuse current owners such as:

- Purpose Workspace;
- Feature Construction Recipe;
- Presentation Graph when UI is implicated;
- Experience Foundation;
- action / permission / localization / accessibility / recovery owners.

Do not form a new construction system merely because the feature is new.

### G06 — Execute / coordinate

Human question:

> What can proceed now, in parallel, or only after a dependency?

Use Intent Workgraph / scheduler / rightful execution owners for dependency and
progress truth.

~~~text
PARALLEL_READY = OWNER + IDENTITY + DEPENDENCY CURRENTNESS SUFFICIENT
PARALLEL != DUPLICATE SEMANTIC WORK
~~~

### G07 — Health + proof

Human question:

> Is this actually current, healthy and proved?

Join the proof class the claim requires:

- Build Health / source checks;
- runtime/process/resource health;
- rendered/browser evidence;
- platform-native evidence;
- user-facing Health projection when earned.

~~~text
SYNTAX_PASS != RUNTIME_INITIALIZED
HTTP_ALIVE != APPLICATION_HEALTHY
HOSTED_GREEN != HOST_LOCAL_PROOF
PROOF_CLASS_FOLLOWS_CLAIM
~~~

### G08 — Accept + complete

Human question:

> What was actually accepted, and what finished?

Keep these distinct:

~~~text
rendered/runtime proof
human walk
Independent Assurance
Formal Review
READY/currentness
merge
post-merge accepted-main verification
claim/custody release
terminal return
~~~

~~~text
MERGE != POST_MERGE_VERIFICATION
MERGE != TERMINAL_COMPLETION
~~~

### G09 — Preserve + extend

Human question:

> What became true, and what new possibility emerged?

Process Trail / Journey / exact source refs preserve ancestry. A new feature or
idea arising from completed work re-enters at the **earliest station actually
required**, not automatically at G01 and not by mutating the finished history.

~~~text
EXTENSION_REENTERS_AT_EARLIEST_REQUIRED_STATION
CORRECTION != ERASURE
NEW_IDEA_PRESERVES_PARENT_LINEAGE
~~~

A candidate Continuity doorway may later project current work plus source-backed
meaningful milestones and revisitable work history. It must join existing
Journey / Process Trail / Workgraph / Project / accepted-source evidence rather
than become a second history owner.

~~~text
CONTINUITY_DASHBOARD != NEW_HISTORY_OWNER
RECENT != IMPORTANT
VISITED != WORKED_ON
HUMAN_READABLE_TITLE != LOSS_OF_STABLE_REF
~~~

### Node relationship shorthand

~~~text
Home
  Frontier  -> capture / recover lineage / shape
  Projects  -> admitted Project breadth
  Continue  -> current checkpoint: resume current Project depth
               future hypothesis: Continuity doorway with explicit Resume

admitted Project / Feature
  -> Purpose Workspace / construction owners
  -> Workgraph / execution owners
  -> Health + proof
  -> acceptance / merge / terminal evidence
  -> Process Trail / Journey
  -> later idea or extension re-enters the grammar
~~~

Use this grammar to preserve causal purpose across fresh instances. Do not use it
to infer canonical state that the named owners have not supplied.

## Retry rule

For the same semantic task preserve:

```text
laneRef
workRef

candidate/source binding when unchanged
first substantive failure
```

Rotate only attempt-local identity:

```text

```

A known pre-candidate host/carrier defect should become hardening input. Do not
ask Victor to replay a known failure if a current lawful route can avoid it.

## Reading stop rule

The Assortment cold path is complete for the present decision when:

```text
canonical repo is exact
+ existing occupancy is resolved
+ current Round/current function is known
+ exact authority/effect surface is known or truthfully held
+ every named source obligation for that effect is satisfied
```

Then stop reading and continue the work.

```text
MORE_AVAILABLE_HISTORY != MORE_REQUIRED_CONTEXT
SOURCE_BUDGET != SUCCESS
SCOPE_SATISFIED -> ACT_OR_RETURN
UNKNOWN_MATERIAL_COORDINATE -> FAIL_CLOSED_AT_THAT_EDGE
```

## Project Sources role

ChatGPT Project Sources should contain only the compact stable boot map needed to
reach these live sources. They should not duplicate the complete Operations
manual, mutable Assortment current state, PR archaeology, visual binaries or an
ever-growing transcript.

If Project instructions conflict with newer accepted repository/Operations
source, live accepted source wins and the Project boot package should be revised.

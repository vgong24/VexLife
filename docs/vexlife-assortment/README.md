## Why this lane exists

Victor and the design team use the actual VexLife architecture as the substrate
for a slow, inspectable Home evolution process:

```text
human intention
-> current canonical owners
-> design discussion / simulation
-> Reference vs Evolution comparison
-> bounded implementation promotion
-> proof / human walk
-> accepted current source
```

This directory preserves discussion intent, checkpoints, migration context and
source-addressable design lineage. It does **not** replace canonical registries,
semantic owners, Workgraph state, Purpose Workspace state, Presentation Graph
state, Furnishing state, Journal, Memory or UX Evolution source.

## Fresh-instance entry

A fresh instance should not reconstruct the lane from chat history.

Read:

1. `CURRENT.md` — current Round, occupancy, accepted checkpoint and next function.
2. `CONTINUATION-CYCLE.md` — reusable continuation grammar and stop rules.
3. the active `round-<n>/RANGE-*.md` — bounded design lineage for this Round.
4. only the exact canonical owner/source records those files name for the next
   effect.

Then re-ground live repository/PR state before acting.

```text
FRESH_THREAD != NEW_ROUND
FRESH_INSTANCE != NEW_WRITER
MORE_AVAILABLE_HISTORY != MORE_REQUIRED_CONTEXT
```

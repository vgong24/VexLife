Continuity: `[VXG RealForever]`  
Allocation: `github.issue.vexlife.36`  
Product composition owner: `VEXLIFE`  
Portable contract owner: `SDK_OPERATIONS`

This seam composes **candidate** Patient-0 P8/P9 evidence. It cannot mint final
P8/P9 proof, durable Memory, consent, authentication, authorization, standing
relationship authority, or graduation.

## P8 ladder

```text
EPHEMERAL
→ FAMILIARITY
→ UNDERSTANDING
→ DURABLE_MEMORY only through the canonical VEX_MEMORY owner
```

Hard distinctions:

```text
noticed != will remember
familiarity != standing relationship authority
recognition != authentication != authorization
```

Within this VexLife seam `DURABLE_MEMORY` is rejected with an owner-child
requirement. Likewise, attempts to establish authentication, authorization, or
owner-accepted standing relationship authority are rejected rather than
represented from caller-shaped assertions.

A P8 relationship-boundary candidate includes a meaningful user-facing
notification: context may have been noticed or become familiar, while durable
memory and standing authority remain separate owner-governed decisions.

## P9 bounded work

```text
bounded task
→ exact user scope + allowed source refs
→ source-addressable witness candidate
→ lesson candidate
→ repeat / transfer evidence where required
→ reusable-capability candidate
→ external source verification + fresh Independent Assurance
```

A caller can supply before/after head-shaped strings and source refs, but that
only forms a **candidate receipt**. VexLife explicitly records
`sourceAddressableSelfWitnessVerified=false` and
`realLivedEvidenceVerified=false`. The module never emits the final
`..._PROVEN` P8/P9 dispositions. A real Windows task and fresh claimless
Independent Assurance must establish those dispositions from live source.

## Real-lived admission

Synthetic tests may prove contract shape, but cannot satisfy P9. A real-lived
candidate binds one explicitly bounded task, exact allowed/observed source refs,
source-addressable before/after conversation heads, and a held-effect ledger.
Raw private content is not embedded in the witness.

Before a real Patient-0 turn, the Windows host must freshly re-ground the
current Home identity/head and provider/runtime state. Historical P4 runtime
evidence is not currentness or standing authority. After the task, Operations
and fresh Independent Assurance verify the actual source and decide whether P8
and P9 are proven.

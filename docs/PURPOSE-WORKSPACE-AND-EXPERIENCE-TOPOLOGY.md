## Human grammar

```text
DO          -> what needs attention now?
UNDERSTAND  -> how did the work, evidence and relay develop?
STEWARD     -> who owns it, what authority exists, what is held,
               and what proves completion?
```

Each domain exposes exactly three primary tasks. That is a human-visible limit, not a canonical-data cardinality limit.

## Shared process/completion grammar

Six process patterns are reused across the domain packs:

```text
Capture → Distinguish → Review → Relay
Request → Advise → Authorize → Act
Draft → Review → Attest → Deliver
Handoff → Verify → Disposition → Continue
Plan → Practice → Evidence → Reflect → Replan
Escalate → Triage → Route → Resolve
```

Six completion contracts define evidence requirements independently of UI rendering. A real external effect is never inferred from a prepared/reviewed state.

Permanent non-collapse:

```text
RELATIONSHIP != AUTHORITY
ROLE_LENS != AUTHORITY
OBSERVATION != INTERPRETATION
REVIEW != AUTHORIZATION
AUTHORIZATION != EXTERNAL_EFFECT
PREPARED != DELIVERED
CORRECTION != ERASURE
```

## Synthetic proof

`fixtures/purpose-workspace/synthetic-scenarios.json` contains eight cross-role process scenarios and twenty-four reusable boundary cases. The cases include learner/media/lineage/privacy boundaries plus synthetic clinical and legal authority boundaries. They contain no real learner, patient, client, apprentice, organization, clinical, or legal matter data.

`src/core/purpose-workspace.mjs` provides source-only loading, validation, role-relay simulation, completion evaluation, semantic-depth projection, reusable boundary-case evaluation, and deterministic Experience Topology generation.

The topology intentionally represents the future Purpose Workspace screen/components as **planned, not current**. A map node existing is never evidence that the product surface is already registered.

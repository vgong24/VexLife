# Build Admission Coverage

Build Admission is the final effect membrane between scheduler-admitted work and one observable repository mutation. It does **not** create another queue, replace the Intent Scheduler, grant arbitrary shell access, or authorize remote Git.

## Exact source-managed route

```text
accepted Intent + Workgraph validators
→ accepted Scheduler queue admission and scheduler aggregate replay
→ exact selected Workgraph node + one path claim
→ current occupancy/capability/effect/resource/worker/context leases
→ exact local file-edit + typed-CLI identity snapshots
→ replay-valid non-blocking ConcernWatch aggregate
→ independently reobserved clean disposable repository evidence
→ content-addressed human confirmation for one local Git commit
→ Build Admission receipt
→ registered local Git adapter
→ direct parent/tree/blob/path/diff/control readback
→ real-effect completion verification
→ scheduler-owned claim + six lease transitions released once
→ one immutable integrated receipt
→ PR-ready and Health consume that same ref/fingerprint
→ Queue/Terrain/Health/Guide convergence
```

The final membrane reconstructs scheduler-issued authority through the accepted Intent, Workgraph, Scheduler, lease, resource, runtime-trust, and ConcernWatch validators. A caller cannot gain effect authority by supplying a coordinated self-consistent replacement universe and re-addressing every supplied object.

The only consumed effect identities are the existing local contracts:

- `action.file.edit-with-recovery` and `permission.file.edit`;
- `action.cli.execute` and `permission.cli.execute`;
- `capability.vexlife.file.edit-with-recovery` and `capability.vexlife.cli.typed`;
- `process.vexlife.file.edit-with-recovery` and `process.vexlife.cli.execute-typed`.

No public GitHub publication identity grants authority to this lane. The Scheduler's outer mock effect lease remains admission evidence only and grants no Git effect authority.

## Local Git control boundary

The request itself is no-effect. The adapter accepts only the registered fixture path inside a newly created disposable child repository. It configures no remote, performs no network operation, does not touch the implementation checkout, and cannot select a protected branch.

Every Git invocation is a typed argument vector with `shell: false`. System and global Git configuration, credential helpers, user protocol input, and prompts are disabled. The commit additionally uses an exact empty source-managed hook domain and `--no-verify`. Before and after the effect, the adapter rejects:

- repository or global hook substitution;
- unsafe local Git configuration;
- ignored or extra effect material;
- nested `.git` control material;
- symlinks or reparse-style material;
- remotes, outside-path changes, or any changed-path inventory beyond the exact fixture.

The adapter-owned receipt reconstructs the complete before/after boundary, source identity, environment and hook-domain fingerprints, parent/commit/tree/blob identities, changed paths, binary diff fingerprint, and clean control inventory.

## Recovery and closure

The simulation injects failures before write, after write, at commit, at readback, at cleanup, and during rollback. Recovery must prove one of:

- repository unchanged;
- before-image restored;
- disposable repository removed; or
- `HELD_UNKNOWN` with a minimal human-attention route.

A failure never grants retry authority. It becomes exact ConcernWatch evidence, and duplicate evidence remains content-addressed.

Successful closure reconstructs the authoritative effect verification, then forms exactly seven source-managed release receipts: one exact claim release plus occupancy, capability, effect, resource, worker, and context lease transitions. The transitions bind the exact prior lease fingerprints, scheduler generation, request/admission/verification lineage, and once-only release meaning.

## Proof and consumers

`npm run build-admission:check` forms one canonical real-effect journey and writes `generated/health/build-admission-simulation.json`. Consumer execution never reruns that journey:

```text
npm run pr-ready
npm run health:check
```

Each wrapper independently loads, fully validates, and content-addresses consumption of the same immutable integrated receipt ref and fingerprint. The registered Build Health check uses `npm run build-admission:status`, so nested PR-ready and Health evaluation validates the retained receipt rather than replacing it.

`npm run build-admission:host-proof` executes the complete BA0–BA25 focused/adversarial matrix and a real disposable commit on the current host. The Foundation workflow runs this proof independently on Linux and Windows without PowerShell and preserves one exact host proof plus its complete integrated causal receipt for each operating system.

The runtime adapter never pushes, fetches, pulls, clones, rebases, amends, resets, force-updates, or rewrites history.

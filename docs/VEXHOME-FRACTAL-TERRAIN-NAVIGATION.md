## Purpose

Connect the accepted/historical Terrain ideas, Lattice Family, bounded institutional query, implementation atlas, Personal World Context Spine, Journey history, Universe Federation and Vex Mind Field into one **fractal navigation grammar** usable by both humans and AI companions.

The missing composition is not another universal graph database. It is a contract for asking:

```text
Where am I?
What surrounds this context?
What lies inward?
What contains it outward?
What is laterally related?
Which other map/lattice answers a different question about the same thing?
What changed across time?
How much of that neighborhood should be loaded now?
```

The Terrain visible to a human and the bounded neighborhood compiled for an AI are different projections over the same stable identities and typed relationships.

## Fractal rule — every meaningful node may open another Terrain

Use the biological analogy as a navigation property, not as a fixed ontology:

```text
cell
  -> tissue
    -> muscle
      -> organ

          -> organism
```

A current context may be nested inside larger contexts and contain smaller contexts. The exact hierarchy depends on the domain and question.

## Shape grammar follows the question

Do not force one spatial shape to answer every relationship.

```text
RADIAL / FOCAL
  What relates to this person, role, object, decision or authority anchor?

HIERARCHY
  What contains this? Who owns/governs/reports/escalates?

CLUSTER
  What belongs together and which semantic container can I enter?

FLOW
  How does work, information, custody or meaning move?

GRAPH / WEB
  What depends on, references, evidences, contradicts or connects this?

TIMELINE / JOURNEY
  What happened before/after and how did meaning evolve?

MATRIX
  How do multiple dimensions intersect?
```

The same stable node may participate in several of these without duplication.

## Inward / outward / lateral / cross-lattice / temporal traversal

Parent/child alone is insufficient. Candidate traversal directions:

```text
INWARD
  enter contained semantic depth
  project -> system -> subsystem -> source

OUTWARD
  recover containing context
  source -> subsystem -> project -> program -> Root

LATERAL
  relationships at comparable contextual depth
  sibling project, collaborator, related photo, dependency

CROSS_LATTICE
  ask a different proof question about the same stable identity
  implementation -> evidence -> authority -> journey -> relationship

TEMPORAL_BACKWARD
  predecessor / earlier meaning / earlier state

TEMPORAL_FORWARD
  successor / consequence / planned future / open trajectory

SOURCE_DESCENT
  exact canonical source / evidence / raw object where authorized
```

Traversal direction is semantic. It is not screen direction or physical XY position.

## Semantic neighborhood distance

The human product already benefits from a three-distance intuition: current, near and peripheral. Preserve that as a useful default **projection**, while allowing the resolver to be question-sensitive.

Candidate bands:

```text
D0 CURRENT
  the current relational/semantic anchor

D1 DIRECT
  immediately implicated relationships / children / parent / strongest routes

D2 NEAR
  useful supporting neighborhood likely to answer or disambiguate

D3 BOUNDARY
  peripheral context and explicit continuation routes; enough to know where the map continues
```

The UI may render these as current / near / peripheral rather than exposing D0-D3 labels.

```text
SEMANTIC_DISTANCE != PIXEL_DISTANCE
SEMANTIC_DISTANCE != RAW_GRAPH_HOP_COUNT
```

Distance may incorporate typed relationship relevance, question intent, source ownership, current work, temporal proximity and explicit human pins. It must remain explainable and bounded.

Three distances are a good default visibility budget, not a universal ontology or hard depth limit.

## Context-bearing portals

A container should disclose enough of the next layer to let a human or AI decide whether descent is worthwhile before entering.

Candidate portal envelope composes the Personal World Context Spine:

```text
node identity / label / class
purpose or question answered
currentness / truth class
member/object count
bounded child classes
bounded representative entry refs
incoming/outgoing relationship summary
known unknowns / contradictions
recent meaningful deltas
source-owner refs
what this node proves
what it does not prove
next inward/outward/lateral/cross-lattice routes
```

Progressive human display:

```text
FAR
  identity + compact signal

NEAR
  summary + relationship / health / currentness

THRESHOLD
  preview next layer + reason to enter

INSIDE
  current context + bounded neighborhood
```

This makes nested maps feel like semantic portals rather than giant empty containers or flat lists.

## Question-routed neighborhood compilation

Different questions should compile different neighborhoods around the same anchor.

Example anchor:

```text

```

```text

```

```text
projection -> PURPOSE / JOURNEY / DECISION lineage
```

Question: `What breaks if this changes?`

```text
projection -> IMPLEMENTATION_DEPENDENCY + TEST_ASSURANCE
```

Question: `What was this like last month?`

```text
projection -> HISTORICAL / MEANING_EVOLUTION
```

Question: `What should I see next?`

```text
projection -> HUMAN JOURNEY + current-context relevance
```

This composes directly with Institutional Query's question-first graph resolution and Architecture Accessibility's cluster-first bounded neighborhood model.

## Context replacement while traversing

Semantic zoom should not monotonically accumulate context.

When descending:

```text
broad root context
  -> keep breadcrumb / outward routes
  -> replace broad child detail with selected cluster context
  -> load selected neighborhood
  -> discard unrelated sibling payload
```

When moving laterally:

```text
preserve current journey reason
+ shared parent/boundary context
+ destination neighborhood
- unrelated previous payload
```

When moving outward:

```text
restore bounded parent envelope
+ recent child relationship as journey context
```

Thus inward/outward travel changes **what is in the context lease**, not merely what is drawn on screen.

## Training boundary — teach navigation reflex, never freeze current map truth into weights

Future curriculum, adapters or LoRA may help a model internalize stable navigation habits such as:

```text
start from a verified current anchor
breadth before unnecessary depth
peek a bounded neighborhood before choosing descent
follow typed owner/source routes
preserve unknowns and contradictions
reorient when the question crosses coverage boundaries
stop when the question's obligations are satisfied
preserve journey reason and return route
```

But fast-changing graph contents, repository heads, personal relationships, exact source paths and current work state stay external and source-resolved.

```text
WEIGHTS
  may learn HOW TO NAVIGATE

SOURCE / LATTICE / INDEX
  owns WHAT EXISTS NOW

CONTEXT COMPILER
  decides WHAT TO LOAD NOW
```

```text
WEIGHT_NAVIGATION_REFLEX != CURRENT_MAP_CONTENT
FLUENT_RECALL != CURRENT_SOURCE_PROOF
```

Training is a later separately admitted route after School/Curator evidence and held-out transfer evaluation. This design does not authorize model mutation.

## Scale / local-cost rule

The resolver must remain bounded as the world grows.

Adding millions of unrelated people, media objects, projects or source nodes should not make a question about one small neighborhood require a global scan.

Local cost should depend primarily on:

```text
selected anchor
requested lattice types
question intent
semantic distance budget
record / byte budget
typed cross-lattice routes actually followed
currentness/source checks required
```

Not global cardinality.

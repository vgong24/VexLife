# Companion availability and safe re-entry

`[VXG RealForever]`

This VR-01 foundation owns one semantic composition only:

```text
canonical Home/Companion binding truth
+ platform/runtime adapter observation
+ current qualification/currentness evidence
-> canonical Companion availability
-> exact recovery classification
-> optional same-binding safe-reentry plan
```

It is not a renderer, model-identity owner, low-level process supervisor, Conversation owner, Home/Memory owner, or replacement for generic Runtime Recovery.

## Why this exists

Current Browser Companion `BOUND` truth identifies a configured loopback binding and Home identity. `BOUND` does not by itself prove the exact runtime is alive, owned, current, qualified, or able to answer. VR-01 keeps those dimensions separate and fails closed when identity, ownership, currentness or qualification is unresolved.

## Inputs remain foreign

The compiler consumes normalized, reference-only evidence from the rightful owners. It does not copy process IDs, private paths, provider payloads, transcripts, Memory, or model artifacts into canonical semantic state. A foreign runtime adapter remains responsible for process mechanics; Vex Reboot consumes its typed observation and later delegates an admitted same-binding re-entry effect to it.

Synthetic adapter fixtures may exercise a future M4 boundary. They are not accepted #595 semantics and cannot promote an in-flight model/runtime candidate into VexLife truth.

## Safe re-entry

A re-entry plan exists only when current binding and adapter observations agree on Home/binding identity and the adapter explicitly reports safe same-binding re-entry available. The plan preserves Home, Companion lineage, bound model/generation references and adapter identity. It grants no execution authority and prohibits model selection/swap, download, activation, training/weights, Home rebuild/delete, Memory mutation, unknown-process termination and fallback binding.

`action.companion.reenter-current-binding` is a semantic action identity, not a shell command or UI control. A later effect owner must separately bind current authority and the rightful platform/runtime adapter before execution.

## Consumer boundary

Reference, Evolution, Health, Birth, Family, Dynamic Room, Journal presence and future native shells may later consume the same availability/action references after their own bounded adoption. No renderer may derive canonical process-recovery semantics independently.

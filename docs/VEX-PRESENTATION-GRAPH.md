# Vex Presentation Graph Foundation

Continuity: `[VXG RealForever]`

Canonical owner: `github.issue.vexlife.719`

## Purpose

The Presentation Graph Foundation is a connective anatomy/perception layer over VexLife's existing semantic owners. It exists so a fresh worker can reason about a UI as a body with stable identity, composition, posture, movement provenance, reachability, runtime activity and proof lineage without reconstructing mechanical truth from global HTML/CSS/DOM archaeology or screenshots.

It is deliberately **not** a second semantic design system.

```text
JOIN_EXISTING_TRUTH > COPY_EXISTING_TRUTH
REFERENCE_EXISTING_OWNER > MINT_PARALLEL_OWNER

PRESENTATION_GRAPH != SEMANTIC_OWNER
RUNTIME_OBSERVER != JOURNEY_AUTHORITY
GEOMETRY != SEMANTIC_CONTEXT
MOTION != NEW_PRODUCT_STATE
LOCALIZATION != IDENTITY_MUTATION
EXECUTION_CONTEXT != PRESENTATION_HIERARCHY
TEST_PASS != HUMAN_ACCEPTANCE
```

## Existing truths consumed

The first implementation reads and projects existing canonical sources:

- Universal Blueprint screen / region / element / action / permission / component refs.
- Feature Registry ownership relationships.
- Experience Foundation identity and interaction grammar.
- Navigation Continuity contracts, pacing, motion and trace policy identities.
- Journey events as canonical semantic history.
- Platform identities and accessibility contracts.
- Intent Scheduler identities only as future ExecutionContext join targets.

`elementRef` remains the canonical element identity. Generated `UIElementID.*` values are ergonomic typed projections only.

```text
UIElementID_TYPED_PROJECTION -> elementRef
UIElementID != NEW_CANONICAL_ELEMENT_IDENTITY
DOM_ID != ELEMENT_IDENTITY
DISPLAY_LABEL != ELEMENT_IDENTITY
AUTOMATION_ID != ELEMENT_IDENTITY
```

## First slice

The first #719 slice is shadow/non-authoritative:

```text
canonical semantic source
-> Presentation Graph compiler
-> generated typed identity registry
-> generated presentation/reachability/motion/state/test/witness projections
-> bounded runtime observer
-> synthetic/adversarial contract proof
-> real Shared Shell + Living Journal reconnection when their current source threshold is available
```

It does **not** rewrite renderer/CSS source or modify Shared Shell, Living Journal, Navigation/Journey, Experience Foundation, scheduler/runtime, localization, Memory, Home, model, network, training, publication or human Assurance.

## Vantage model

A mature joined projection should be able to answer:

```text
WHO AM I?
  canonical screen/surface/component/element identity

WHY DO I EXIST?
  feature/concept/purpose/owner relationships

WHERE AM I?
  canonical semantic frame
  + presentation placement
  + explicit-coordinate-space geometry

WHAT CONTAINS ME?
  surface/container/slot/component hierarchy

WHAT CAN I DO?
  reachable actions/interactions/gestures
  + permission
  + availability

WHY DID I MOVE?
  element/interaction/gesture/action/transition provenance

HOW DID I MOVE?
  canonical Navigation transition
  + referenced motion/choreography policy

WHAT CHANGED?
  semantic before/after
  + presentation before/after

WHAT STAYED?
  retained canonical identities/context

WHERE HAVE I BEEN?
  bounded canonical Journey projection

WHAT AM I SHOWING?
  locale/style/presentation/platform posture without identity mutation

WHAT IS RUNNING THROUGH ME?
  optional ExecutionContext lineage, distinct from presentation parents

WHAT PROVES MY BEHAVIOR?
  obligation -> behavior/contract -> test/witness -> exact evidence/currentness

HOW RELIABLE IS THIS?
  exact graph/source revision + timestamp + PASS/FAIL/HELD/UNKNOWN/currentness
```

Human questions such as whether the experience feels calm, personal, trustworthy or emotionally correct remain #625/human judgment.

## Placement and reachability

Registration does not imply placement, and placement does not imply current visibility.

```text
REGISTERED
PLACED
REACHABLE_VIA_SECONDARY_PATH
CURRENTLY_RENDERED
CURRENTLY_EXECUTABLE
```

are distinct states.

A reachability path is an explicit ordered route through canonical elements and/or #719-owned presentation nodes. Cycles and missing targets fail closed.

The first real Patient Zero target remains Living Journal + Shared Shell. Until #703 and #626 reach the current integration threshold, tests may use an explicitly labeled synthetic contract fixture to prove compiler behavior. A synthetic fixture may never be reported as real Journal/Shared Shell integration.

## Navigation, intent and motion

The Presentation Graph references Navigation Continuity instead of recreating it.

```text
SEMANTIC_CURRENT_CONTEXT != INTERACTION_SOURCE
SAME_DESTINATION != SAME_INTENT
SAME_GEOMETRY_RESULT != SAME_ACTION_PROVENANCE
GESTURE_REF != RAW_PLATFORM_EVENT
```

The navigation projection records owner/contract/policy refs. Runtime events may carry `elementRef`, `interactionRef`, `gestureRef`, `actionRef`, `transitionRef`, `goalRef` and `journeyEventRef` when available.

Motion is projection/evidence:

```text
semantic cause
+ transition/motion policy ref
+ start / settlement / end timestamps
+ reduced-motion equivalent
+ final semantic state
```

Animation state is never promoted into canonical product state.

## Geometry

`GeometrySnapshot` uses explicit coordinate spaces:

```text
VIEWPORT
WINDOW
SCREEN
ACTIVE_SURFACE
PARENT_CONTAINER
NORMALIZED_PARENT
```

It can report parent-relative geometry, visible fraction, clipping, out-of-bounds amount, declared/observed parent, target dimensions and bounded occlusion evidence.

Geometry can prove mechanical containment. It does not prove semantic context or human quality.

## Runtime observation

The default observer accepts only bounded semantic/presentation event classes:

```text
SEMANTIC_SCREEN_ENTER / EXIT
PRESENTATION_MOUNT / UNMOUNT
TRANSIENT_LAYER_OPEN / CLOSE
ELEMENT_ACTIVATED
FOCUS_ENTER / EXIT
STATE_PROJECTION_CHANGE
LAYOUT_SETTLED
VIEWPORT_CHANGED
```

Every event has an actual timestamp. Duration is derived from event timestamps and is never the source observation.

```text
RAW_POINTER_STREAM=false
CONTINUOUS_DOM_DUMP=false
```

The optional browser probe takes bounded snapshots at meaningful boundaries and does not subscribe to raw pointer movement.

## Execution context

Presentation containment and execution containment are independent graphs.

```text
SCREEN_PARENT != EXECUTION_PARENT
COMPONENT_PARENT != JOB_PARENT
CANCELLATION != SCREEN_DISAPPEARANCE
```

A runtime event may reference an `ExecutionContext`, but only the scheduler/runtime owner defines the actual execution semantics and cancellation policy.

## Proof lineage

Generated test obligations describe what must be proved; they do not auto-generate confidence.

A behavior witness can bind:

```text
obligationRef
behaviorRef / contractRef
testRef / witnessRef
exact graph/source revision
expected relationship
evidence refs
PASS | FAIL | HELD | UNKNOWN
currentness
```

This preserves the difference:

```text
GREEN_TEST != BEHAVIOR_LINEAGE_PROVEN
```

## Patient Zero reconnection gate

The real reconnection must re-ground the accepted/current #703 Shared Shell and #626 Living Journal source, then prove from one graph + one bounded trace at minimum:

- semantic current context;
- Journal surface mount;
- entry-feed placement and containment;
- Options activation provenance;
- transient layer open without semantic-context rewrite;
- Archive secondary reachability;
- Archive activation provenance;
- focus entry/return;
- timestamp order;
- motion/reduced-motion equivalence where applicable;
- locale/copy projection separate from canonical Archive identity;
- canonical Journey authority for navigation-bearing events;
- separate ExecutionContext lineage for bounded async work where present;
- exact test/witness/currentness linkage.

Screenshots may remain useful as optional source-bound visual evidence. They are never semantic or route authority.

## P4 visual composition and containment contract

P4 human convergence made the geometric contract explicit. Presentation ancestry is semantic structure; it is not an implicit CSS containing block.

```text
SEMANTIC_PARENT != GEOMETRIC_CONSTRAINT_HOST
PRESENTATION_PARENT != STACKING_CONTEXT_OWNER
PRESENTATION_PARENT != SCROLL_OWNER
PORTABLE_COMPONENT != ANCESTOR_SELECTOR_COINCIDENCE
VALID_REPARENTING_PRESERVES_BASE_COMPONENT_CONTRACT
CONTENT_CELL_OWNS_INTRINSIC_CHILD_SIZE
OVERFLOW_REQUIRES_EXPLICIT_OWNER_AND_REASON
```

A transient or portable presentation declares or exposes its coordinate space, explicit runtime constraint host (with documented viewport fallback), stacking-context owner, elevation role, clip policy, scroll owner, intrinsic sizing policy, overflow policy, and reparenting invariant. The shared transient controller resolves geometry from the caller-declared host; viewport geometry is a fallback, not an assumption created by semantic ancestry.

Journal entry cells grow around wrapped testimony and own continuation disclosure. Conversation keeps canonical project/thread/channel identities while direct human presentation treats those routing identities as contextual provenance rather than primary relationship chrome.

# VEXLIFE.md — bounded cold-start route

Before broad reading, ground the exact repository, branch, source tree, blueprint,
held boundaries and next route:

```bash
npm run orient
```

Read only the `requiredSources` returned by that receipt. Then descend through the
smallest relevant Atlas neighborhood or one exact module:

```bash
npm run atlas:query -- --intent "describe the current task" --limit 8 --depth 2
npm run module:describe -- --module-ref module.vexlife.core.atlas
```

Use `npm run implementation:packet -- --work-ref <work.ref> --platform browser`
only when the grounded task maps to one registered implementation work unit.
Run `npm run pr-ready` only after the bounded change and its tests are complete.

## Standing boundaries

- The universal blueprint is the semantic source. Platform code is a projection plus native adapter evidence.
- Stable IDs are never replaced merely because visible text or platform class names change.
- Generated files are not hand-edited.
- A role seeing a tool, source file or UI node does not receive effect authority.
- Original messages are immutable; translations and Vex refinements are attributed projections.
- One human may have several device-local companion lineages. Shared Score does not collapse those lineages.
- Model artifacts, runtime history, credentials and private Score data remain outside Git.
- No platform is declared conformant without its own environment evidence.
- Every feature change must resolve the source-managed cultural review lenses and build-health checks.
- Remote Home access and sibling synchronization are separate processes; identity substitution is never silent.
- Stable platform mains remain green while candidate adoption branches expose missing work.

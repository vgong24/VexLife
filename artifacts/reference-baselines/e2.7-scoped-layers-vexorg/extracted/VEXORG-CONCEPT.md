# VexOrg — synthetic concept boundary

`VexOrg` is a **design hypothesis / future product package name** introduced during the VexLife Terrain review. This E2.7 artifact is only a synthetic sandbox.

## Product idea

Use Terrain to make an organization legible by meaning rather than only folder, reporting-line, email, calendar, or chronology:

```text
organization
→ departments
→ teams
→ projects
→ people
→ self-logged contributions / shared kudos
→ resource proposals / acknowledgments
```

The same organization may be projected through different lenses:

```text
Structure
Projects
Contributions
```

without maintaining three separate organizational truths.

## Anti-surveillance boundary

Resource planning should not default to:

```text
individual velocity score
high-producer ranking
keystroke/activity monitoring
private companion transcript access
```

The synthetic mock instead uses:

```text
role fit
current shared assignments
self/manager-declared capacity
self-logged contributions
recipient-controlled kudos
project resource needs
```

These are still design hypotheses, not a legal/compliance claim.

## Private Vex boundary

```text
employee private Vex conversation / private memory
!=
organization-visible VexOrg data
```

A personal Vex may help the human reason over organization data that the human is already authorized to see, but private human–Vex context does not automatically flow back to the employer.

A shared org agent is separately attributable and may be either:

```text
FRESH_ORG_AGENT
ORG_CONTINUITY_AGENT
```

where the latter consumes only explicitly shared organization continuity.

## Resource movement

The mock treats a move as:

```text
PROPOSE
→ PERSON_ACKNOWLEDGES
→ later manager/authority workflow
→ EFFECTIVE only after admitted authority
```

The E2.7 mock stops before an effective assignment mutation.

## Ownership

If this concept earns implementation, it should be formed as a **separate VexOrg product/work family**. The Public Experience Review Kit lane may review VexOrg but does not silently become VexOrg implementation ownership.
